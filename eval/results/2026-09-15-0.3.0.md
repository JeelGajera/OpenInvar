# Evaluation — 2026-09-15 (0.3.0)

OpenInvar 0.3.0, measured against the criteria fixed in
[`criteria.md`](../criteria.md) before the run. The third run, and the first
able to *judge* **R′** rather than bound it — which is what the previous run
said the next product change should make possible.

The second report carries the same date because both ran on 2026-09-15; this
one is distinguished by version because that is the difference that matters
between them.

**Verdict: CONTINUE.** No criterion reached its stop threshold. **R′ came in at
63.2%, unchanged to the decimal from the previous run**, still in the
investigate band — and now split by why each reference failed to bind. That
split is the whole content of this report.

## Corpus

Unchanged from the previous two runs, deliberately: the same four repositories
at the same eight commits each.

| Repository | Language | Files | Edges | Slowest revision |
|---|---|---|---|---|
| [rust-lang/log](https://github.com/rust-lang/log) | Rust | 23 | 388 | 0.07s |
| [spf13/cobra](https://github.com/spf13/cobra) | Go | 66 | 1,870 | 0.14s |
| [pallets/click](https://github.com/pallets/click) | Python | 177 | 1,476 | 0.17s |
| [google/gson](https://github.com/google/gson) | Java | 313 | 18,989 | 0.56s |

32 revisions, 28 consecutive commit pairs.

**The corpus does not cover the three languages this version added.** PHP, Swift
and Lua shipped as Tier 2 between the runs and no repository here is written in
any of them, so nothing below says anything about those adapters. Adding one
repository per Tier 2 language would change what the corpus is comparable to,
which is a decision for a run that is not also carrying a criterion change.

## Results

### D — Determinism · **PASS**

**32 of 32 revisions byte-identical**, each analysed twice into worktrees on
different paths. Zero mismatches, as in both previous runs.

Worth stating plainly given what changed in this version: the `tree-sitter`
runtime moved five minor versions and all ten grammars moved with it, and
determinism did not budge.

### P — Precision · **PASS**

**0 of 28 commit pairs produced an error-severity finding**, against a ≤10%
threshold. No warn-severity findings either.

### R — Resolution coverage · **PASS, and still not meaningful**

Median 100.0%, and every one of the four repositories reported exactly 100.0%,
for the third run running. The figure counts `Resolution::Resolved` edges,
`dispatch` stamps every Tier 1 edge `Resolved`, and none of these four
repositories contains a Tier 2 file, so 100% was guaranteed before the run
started. Left in place and scored so the runs stay comparable.

### R′ — Reference-level coverage · **INVESTIGATE**

Median **63.2%**, against a pass line of 65% and a stop line of 50%.

**Identical to the previous run in every repository, to the last reference:**

| Repository | Language | Bound | Attempted | Bound % | Previous run |
|---|---|---:|---:|---:|---:|
| rust-lang/log | Rust | 388 | 764 | **50.8%** | 50.8% |
| pallets/click | Python | 1,476 | 2,371 | 62.3% | 62.3% |
| google/gson | Java | 18,989 | 29,590 | 64.2% | 64.2% |
| spf13/cobra | Go | 1,870 | 2,836 | 65.9% | 65.9% |

That is the result to check first, and it is the one this run most wanted. Three
changes landed between the runs — a `tree-sitter` upgrade, a Rust resolver fix,
and the classification work below — and the measure they were meant not to move
did not move. A metric that shifted here would have meant the split was
rewriting the number it was supposed to be explaining.

#### The split

Adapters now record *why* a reference did not bind. `unbound_outside_repository`
counts only what an adapter can show is outside the tree — a prelude name, a
builtin, a language's own vocabulary — and everything else stays unexplained.

| Repository | Language | Unbound | Outside | Unexplained | Explained |
|---|---|---:|---:|---:|---:|
| pallets/click | Python | 895 | 702 | 193 | **78.4%** |
| spf13/cobra | Go | 966 | 278 | 688 | 28.8% |
| rust-lang/log | Rust | 376 | 100 | 276 | 26.6% |
| google/gson | Java | 10,601 | **0** | 10,601 | **0.0%** |
| **total** | | **12,838** | **1,080** | **11,758** | **8.4%** |

**The aggregate is not the finding, and reporting it alone would mislead.**
8.4% explained invites the reading that nine tenths of the gap is real missed
work. It is not. Java contributes **10,601 of the 12,838 unbound references —
83% of the corpus total — and classifies none of them**, because the Java
adapter has no builtin list to classify against. The aggregate is dominated by
the one adapter that reports zero by construction.

The per-repository figures are the ones that carry information, and they say
something quite different:

- **Python at 78.4%** is what the mechanism looks like where it is wired. Most
  of `click`'s unbound references are the interpreter's own vocabulary.
- **Rust at 26.6% and Go at 28.8%** are wired but partial. Both classify
  builtins and prelude callables; neither classifies a reference into a
  third-party package that resolved to no local module.
- **Java at 0.0%** is unwired, and is most of the corpus.

The previous run opened `log` by hand and found 51 diagnosed unbound references,
every one of them Rust's standard library. This run counts 100 of `log`'s 376 —
nearly twice as many — because classification covers callables the diagnostics
deliberately never reported.

#### What this licenses

It does not license moving the threshold. 63.2% is under 65% and stays under it.

What it licenses is a sharper statement than the previous run could make. R′ is
no longer a single ceiling. For Python it is close to a defect count: 193
unexplained references out of 2,371 attempted. For Java it remains a pure
ceiling, because nothing has been asked of that adapter yet.

**And it names the next change precisely, which a ceiling could not.** The
previous run said "splitting the two needs each adapter to say why it could not
bind". That is done. This run says: the highest-leverage remaining work is the
Java classifier, because Java is 83% of the corpus's unbound references and
currently contributes no information to the figure at all. C# is in the same
position with no repository here to show it.

### T — Performance · **PASS**

Slowest revision **0.56s** (gson, 313 files, 18,989 edges). Median 0.15s.
Threshold was ≤ 60s.

Slower than the previous run at every size — 0.41s to 0.56s on gson — and
faster than the run before that, which was 0.71s. The spread across three runs
on unchanged inputs is wider than any change between them, so this is machine
variance rather than a regression. Two orders of magnitude of headroom either
way.

## What changed since the previous run

The previous report ended by naming one product change:

> R′ cannot currently separate "outside the repository" from "missed", and
> until it can, the number is a ceiling rather than a defect count. […] That is
> the next product change this evaluation points at.

That shipped, and this run is the first that could use it. Also landed since:
a `tree-sitter` 0.22 → 0.27 upgrade with all ten grammars, a Rust fix for
generic type parameters being reported as missing types, a delta fix so edges
that only moved are no longer reported as changed, and PHP, Swift and Lua as
Tier 2 languages.

None of those moved a single number in R, R′ or D.

## Reproducing

```bash
cargo build --release
python3 eval/run.py --commits 8 --out eval/results/run.json
python3 eval/summarise.py eval/results/run.json
```

The run clones into a temporary directory and removes each repository after
measuring it. Network access to github.com is required.
